# 媒体资产与工程备份

## 默认存储

新项目使用 `UnitaleWorkspaceDB`。`projects` 存项目概要，`scripts` 按脚本保存，`assetMetadata` 与 `assetBlobs` 分别存媒体元数据和 Blob，`recentDirectories` 仅保存用户授权过的目录句柄。资产 ID 为随机不可变 ID；替换媒体时产生新 ID，台词与资源库只保存引用。TTS 的 `audio_path` 仍使用服务端文件路径，不使用资产 ID。

应用不读取或迁移旧 `UnitaleDB`。旧数据库保留，设置页提供明确的删除操作。已失去引用的媒体在保存成功后按项目引用扫描清理，新写入的媒体有两分钟宽限期，以避免清理正在提交的素材。存储诊断显示媒体总量、孤儿、缺失引用、解码缓存和浏览器配额估算；配额估算不保证后续写入成功。

原始及处理后的 `AudioBuffer` 共用 128 MiB 的 LRU 预算。播放中的缓冲区会暂时保留；单个缓冲区超过预算时只供当次使用。切换脚本、替换媒体或卸载视图时释放对应 Blob URL。

台词的音频状态由 `audioAssetId` 决定，播放时才按 ID 读取媒体并建立临时 URL。台词中的滤波器、音效和 BGM 分别保存 `filterId`、`sfxId` 和 `bgmId`；分析结果中的名称在写入脚本时解析为 ID，旧的名称引用不参与播放或导出。波形只在画布进入视口时排队解码，同时最多运行两个解码任务。

## 备份与导入

工程导出为 `formatVersion: 1` 的 ZIP 归档，使用 zip.js 的 ZIP64 和 Web Streams 支持，包含 `manifest.json`、`project.json`、逐脚本 JSON 和独立媒体数据。每个资产在清单中记录 ID、类型、MIME、字节数、CRC32 与分块位置。媒体分块最大 8 MiB。支持文件流写入的浏览器输出一个归档；其他浏览器按脚本及资产顺序输出目标不超过 128 MiB 的分包，并在工具栏逐包下载。导入时一次选择所有 ZIP 分包；缺包、重复包、资产大小或校验值不符都会报错。

导入先把资产和脚本写入临时项目，全部成功后才切换当前项目。失败时尝试回收已写入的临时资产。旧 Base64 JSON 格式不再导入或导出；如需保留旧开发数据，请先在旧版本中处理。

音频导出每次最多离线渲染两分钟。支持文件流写入且总 WAV 小于 4 GiB 时输出单文件；否则下载编号 WAV 分段。视频每段最多两分钟，输出编号 MP4，避免将整书视频封装到一个内存缓冲区。当前视频导出沿用原有纯画面轨道行为，配音请使用 WAV 导出。

## 本地目录模式

在设置页选择“迁入本地目录”，应用会在所选目录中创建 `Unitale_...` 子目录。迁入时逐项复制并校验原媒体，最后写 `manifest.json` 并切换后端；失败时仍使用原 IndexedDB 项目。目录模式以该目录内的 manifest、逐脚本 JSON 和资产文件为真相来源。IndexedDB 只记录最近使用的目录句柄与当前选择。清除网站数据后，可重新选择该 `Unitale_...` 子目录打开项目。

浏览器可能在刷新后要求重新授权目录。设置页会显示权限错误，并提供“打开目录项目”。不支持 `showDirectoryPicker()` 的浏览器仍使用默认浏览器存储和 ZIP 备份。OPFS 与网站同属 origin 配额，不作为用户可见目录的替代。

## 检查

运行 `npm test`、`npm run typecheck` 和 `npm run build`。自动测试覆盖资产写入、引用扫描、缓存淘汰、ZIP 往返与失败回滚、缺少分包，以及目录重新打开。浏览器中的配音、混音、字幕、音频和视频导出仍按[人工验收清单](acceptance.md)检查。GitHub Pages 保持手动发布。
