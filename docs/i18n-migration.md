# 中英文共用应用：迁移准备

## 当前状态

- 中文入口 `index.html` 加载 `src/main.ts`、`src/App.vue` 和共享组件。
- 英文入口 `index_en.html` 仍是约 5900 行的独立旧版页面，包含旧界面、状态和业务实现。本轮保持它原样，直到新应用的英文文案全部齐备。
- `vite.config.ts` 已构建两个 HTML 入口。切换时保留 `/Unitale/index_en.html`，但使它像中文入口一样加载 `src/main.ts`，不再复制 Vue 模板或业务脚本。
- `src/i18n/` 已提供按 `<html lang>` 选择语言的词条、类型约束和 Vue 注入。新版组件中的静态文案、用户提示、错误和进度信息已提取到 `zh-CN.ts`。`en-US.ts` 仅保留此前完成的 19 条翻译，其余词条暂时回退中文。当前没有语言切换按钮；英文旧入口也尚未使用它。

## 边界

1. **界面语言**只控制 UI 文案。为便于先提取、后翻译，现阶段大多数词条用中文原文作消息 ID；早期导航词条保留语义 ID。带变量的文案使用 `{name}` 等占位符，避免拼接导致中英文语序错误。`npm run typecheck` 会检查中文消息 ID 和已写英文词条的占位符；英文补齐后应恢复英文目录的完整键检查，再切换入口。
2. **用户内容**不翻译。小说原文、台词、角色名、音色名、导入的素材名和已保存的 Prompt 均原样保留。
3. **业务标识**不翻译。`UnitaleDB` 版本 1、`storageKeys`、脚本块 `type`、JSON 字段、API 请求字段和导出工程格式必须维持兼容。`旁白`、情绪名与强度等中文值目前参与分析、匹配或存档，不能简单替换为英文显示值；若需英文展示，应增加显示映射。
4. **生成内容的语言**独立于 UI。旧英文页的默认分析 Prompt 和音色描述 Prompt 明确要求英文输出；新版中文 Prompt 没有这个要求。切换时建议增加独立、可见的生成语言偏好：首次进入时按原入口选取旧默认行为，之后切换界面语言不改变该偏好。已有自定义 Prompt 优先且不能被覆盖。该偏好需使用独立的新存储键，不得复用业务键或悄悄改写工程 JSON。Prompt 不进入普通 UI 词条。相关位置：`useUnitaleWorkspace.js` 的 `defaultPromptTemplate`、`defaultVoicePromptTemplate` 及模板保存和调用代码。
5. **页面入口与语言切换**：未来 `index_en.html` 只保留英文 `lang`、标题、静态依赖和同一个模块入口。界面内切换语言时更新 `<html lang>` 和标题；若切换网址或刷新，需确认未保存的编辑内容和正在进行的任务如何处理。语言偏好不可复用现有业务存储键。

## 切换前验收

- `npm run typecheck`、`npm run build` 通过；`dist/index.html` 与 `dist/index_en.html` 都存在并加载同一份应用代码。
- 两个入口的五个导航页、创作台四个步骤、弹窗、错误和进度没有遗漏中文界面文案；用户作品中的中文不计入此项。
- 同一来源下从中英文入口打开原有 `UnitaleDB` 存档，脚本、角色、音频、模型配置及自定义 Prompt 均一致；切换语言不会重置它们。
- 实测英文和中文默认 Prompt、用户自定义 Prompt 的生成语言；确认角色名、情绪与音色绑定不会因界面翻译而变化。
- 检查导入/导出工程、字幕、音频、视频和移动端布局；通过人工端到端验收后再替换旧英文入口并发布。
