# 工程化迁移后的人工验收

请在手动启用 GitHub Pages 发布前，用 `npm run build` 和 `npm run preview` 的产物完成以下检查。测试数据先导出完整工程文件备份。浏览器存储按网站来源隔离；从原作者域名切换到 fork 域名时，请通过工程文件搬迁。

- 打开中文版 `/Unitale/` 和英文版 `/Unitale/index_en.html`；检查导航、图标、手机宽度布局及静态音频资源。
- 在原有网站来源上打开新版，确认已有 `UnitaleDB` 存档、模型配置、脚本和素材恢复；刷新后再次确认。
- 新建、重命名、切换、删除脚本；编辑原文、台词、BGM 和背景图片块；检查角色与音色绑定。
- 导入 TXT；导出完整工程，再在测试环境导入，核对脚本、素材和配置。检查 SRT 与音频导出。
- 使用实际 LLM/TTS 服务检查分析、角色音色生成、单行与批量配音、停止生成、顺序播放和音色试听。
- 检查波形裁剪、音量、语速、音效及 BGM 混音；生成视频并检查横竖屏输出。
- 确认浏览器控制台没有启动错误，构建产物没有请求缺失的 `voice/`、`vendor/` 或图标文件。

完成验收后，在仓库 Pages 设置里选择 GitHub Actions 来源，并从 `dev` 分支手动运行 `Deploy to GitHub Pages` 工作流。本工作流不会因提交自动发布。
