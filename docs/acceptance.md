# 媒体架构改造后的人工验收

在手动发布 GitHub Pages 前，用 `npm run build` 和 `npm run preview` 的产物完成以下检查。先运行 `npm test`，并用可舍弃的测试数据验收。新版不导入旧 Base64 JSON，也不自动读取旧 `UnitaleDB`。

- 打开中文 `/Unitale/` 与英文 `/Unitale/index_en.html`，检查导航、语言切换、生成语言、手机宽度布局和静态资源。两个入口应共用同一项目数据。
- 新建多个脚本，编辑原文、角色、台词、BGM 和背景图片；刷新后确认全部恢复。切换脚本时确认音频状态正确，模型配置及 API 行为不变。
- 上传两个同名但内容不同的音色、音效或 BGM，分别试听并刷新；确认内容没有互相覆盖。重复生成一行 TTS，确认旧音频被新音频取代，失败时旧音频仍可用。
- 删除台词、脚本和素材后刷新存储诊断；确认缺失引用为零、孤儿数量随保存和宽限期结束而收敛。模拟浏览器配额不足或拒绝写入，确认有失败提示且旧引用仍可播放。
- 导出单 ZIP、按需下载所有分包，再一次选择全部分包导入。检查各脚本、角色音色、背景图片与媒体内容一致；故意漏选一个分包，确认拒绝导入且原项目未被替换。
- 在创作台和小说制作页顶部切换分析模型与配音模型，确认两页显示同一当前选择；模型配置、音色、音效和 Prompt 页不显示选择器，创作台页内不再出现重复入口。使用实际 LLM/TTS 检查中英文分析、音色生成、单行与批量配音、取消、顺序播放、波形裁剪、音量、语速、音效和 BGM 混音。检查 SRT、WAV 及 MP4 分段导出。较长脚本应每两分钟生成一段；支持流式文件写入的浏览器可得到单个 WAV。
- 用含卷首内容、数百章和 GB18030 编码的 TXT 检查“小说制作”：预览默认显示第一章，切换编码、跳转中段与末章后取消应不产生新小说；确认导入后全部章节均在，且没有预选或自动分析。搜索或状态筛选变化应清空当前选择，翻页和打开单章再返回应保留选择与位置。检查按序号选择不包含卷首内容，部分配音显示实际条数，未完成章节无法批量导出。
- 在小说中连续打开上一章、下一章并重命名，返回列表后刷新，确认章节内容和标题保存；在本章选择库音色并设为本书默认，确认同名角色继承、其他小说不受影响、有意设置的本章例外不被覆盖。用实际 LLM/TTS 检查所选章节的停止、失败重试和 WAV＋SRT ZIP 导出。
- 把已有台词引用的音效、BGM 和滤波器重命名，再播放和导出，确认仍按原 ID 生效。把波形滚出视口后打开长脚本，确认离屏波形不触发解码；滚回时才出现波形。让音效从第 119 秒开始并跨过第 120 秒，确认 WAV 两段都保留该音效，视频画面也覆盖尾音时长。
- 在支持目录写入的浏览器迁入本地目录，刷新并重新授权后打开；清除该网站数据，再仅凭 `Unitale_...` 子目录打开项目，核对脚本及媒体。迁入中断时应继续使用原 IndexedDB 项目。在不支持目录写入的浏览器检查 ZIP 备份路径。
- 使用含多个脚本和大量短音频的测试工程，记录打开、导出、导入时的浏览器峰值内存和存储估算；确认打开工程不会预解码全书，解码缓存保持在预算附近。检查控制台没有启动错误或资源 404。

验收完成后，在仓库 Pages 设置选择 GitHub Actions 来源，从 `dev` 分支手动运行 `Deploy to GitHub Pages`。提交不会自动发布。
